Vamos a construir el sistema de un delivery, pero cada grupo escribe una parte distinta del mismo programa. El profesor entrega la clase raíz y los dos main. Lo demás es de ustedes: cinco interfaces y once clases. Al final de la sesión compilamos todo junto, en pantalla, y vemos si corre.

Cómo vienen los archivos

El Javadoc es la especificación. Sus archivos no traen instrucciones sueltas: traen el Javadoc completo de cada método — qué hace, qué recibe, qué devuelve, qué excepción lanza — y el cuerpo vacío. Ustedes leen el contrato y escriben el código que lo cumple.

/**

 * Sobre eso se suman $700 por cada ingrediente extra.</p>
 *
 * @return el precio final en pesos
 */
@Override
public double calcularPrecio() {
    // TODO G1
}

Las cinco interfaces van un paso más allá: llegan vacías. Traen escrito en su Javadoc qué métodos debe exigir el contrato, con qué tipos y qué debe lanzar, y el grupo dueño lo traduce a Java. Es lo primero que se hace hoy.

El anillo de contratos

Cada grupo es dueño de una interfaz y está obligado a cumplir la del vecino. El círculo se cierra: si un grupo no entrega, no compila nadie.

ContratoLo escribeLo cumple
PreparableG1 Cocina→G2 en Bebida y Combo
DescontableG2 Bebidas→G3 en Pedido
FacturableG3 Pedido→G4 en MedioPago
CobrableG4 Pagos→G5 en Repartidor
CalificableG5 Reparto→G1 en Pizza y Sushi

Las seis reglas

  1. Primero el contrato, después el código. Nadie escribe el cuerpo de un método antes del minuto 40. Mientras una interfaz esté vacía, el grupo que la implementa no compila.
  2. Cada grupo toca solo sus archivos. Si necesitan que otro cambie algo, se lo piden a ellos. No se edita el archivo de otro grupo.
  3. Nadie modifica Producto.java, Verificador.java, MainDemo.java ni MainPruebas.java.
  4. Las firmas no se cambian sin avisar. Si tocan un método de su interfaz, el grupo que la implementa deja de compilar en ese mismo segundo.
  5. Los atributos van private y se validan en el constructor o el setter, lanzando IllegalArgumentException.
  6. Compilen temprano y seguido con la línea de javac de su ficha. No esperen al final.
  7. Truco: un método que declara return y no lo tiene no compila. Mientras trabajan, dejen un return 0; provisorio para poder ir compilando.

Los tres errores que van a ver

Dice el compiladorQué pasó
method does not override…La interfaz que deben cumplir todavía está vacía. No es problema de ustedes: es el grupo dueño el que no la ha escrito.
missing return statementEl método está vacío. Ese es su trabajo. Para ir compilando a medias, un return 0; provisorio.
constructor X cannot be applied…El constructor está vacío y Java intenta llamar solo a super(). Falta el this(...) o el super(...) con sus parámetros.

Cómo corre esto

javac *.java        # los 20 archivos juntos. Solo compila si los 5 terminaron.
java MainDemo       # la demo narrativa que se proyecta
java MainPruebas    # el banco de pruebas: 40 lineas [OK] / [FALLA]
