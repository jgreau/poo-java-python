Java obliga

El nombre del archivo es parte del código

Renombrar la clase y no el archivo produce un error explícito: class Perrito is public, should be declared in a file named Perrito.java. Es el ejercicio E0.1.

Python no obliga

Pero la convención manda

El archivo y la clase pueden llamarse distinto y Python no se queja. La costumbre es cuenta_bancaria.py con class CuentaBancaria.

La sorpresa

Los imports

Java ve solo todas las clases de la carpeta. Python necesita que le digas de qué archivo sacar cada cosa, siempre. Borrar el import da NameError.

Quinto movimiento

Crear una clase es crear un archivo

Se suma a los cuatro de siempre: archivo nuevo, nombre correcto, recompilar — y en Python, agregar el import donde se use.

DEMO 02

Encapsulamiento

Un atributo público es la caja registradora abierta; uno privado obliga a pasar por el cajero. La cuenta valida cada depósito y cada giro, y no expone un setSaldo() jamás.

Momento ajáJava prohíbe con el compilador. Python solo avisa: __saldo se renombra a _CuentaBancaria__saldo y sigue ahí, a la vista de quien lo busque.
JavaCuentaBancaria.java
class CuentaBancaria {
    private int saldo;      // privacidad REAL

    public int getSaldo() {
        return this.saldo;
    }
    // no existe setSaldo(): el saldo solo
    // cambia con reglas de negocio
    public void girar(int monto) {
        if (monto > this.saldo) {
            System.out.println("Saldo insuficiente");
            return;
        }
        this.saldo -= monto;
    }
}
// cuenta.saldo = 999999;  <- NO COMPILA
Pythoncuenta_bancaria.py
class CuentaBancaria:
    def __init__(self, saldo):
        self.__saldo = saldo    # name mangling

    @property                   # se lee como atributo,
    def saldo(self):            # pero ejecuta el metodo
        return self.__saldo
    # sin @saldo.setter -> solo lectura

    def girar(self, monto):
        if monto > self.__saldo:
            print("Saldo insuficiente")
            return
        self.__saldo -= monto

cuenta._CuentaBancaria__saldo = 1   # si se puede
DEMO 03

Herencia

En vez de copiar y pegar entre Auto y Moto, lo común sube al padre. La prueba para saber si corresponde herencia es decirlo en voz alta: un Auto es un Vehículo.

Momento ajáAgregar un atributo al padre rompe a todos los hijos de golpe. La herencia acopla, y esa lección duele más viéndola que escuchándola.
JavaVehiculo.java · Auto.java
// ===== Vehiculo.java =====
public class Vehiculo {
    protected String modelo;    // visible para los hijos

    public Vehiculo(String modelo) { this.modelo = modelo; }

    public void describir() {
        System.out.println("Vehiculo " + modelo);
    }
}

// ===== Auto.java =====   (sin import)
public class Auto extends Vehiculo {
    public Auto(String modelo) {
        super(modelo);          // SIEMPRE primero
    }
    @Override                   // el compilador verifica
    public void describir() {
        System.out.println("Auto " + modelo);
    }
}
Pythonvehiculo.py · auto.py
# ===== vehiculo.py =====
class Vehiculo:
    def __init__(self, modelo):
        self._modelo = modelo   # "_" = convencion

    def describir(self):
        print(f"Vehiculo {self._modelo}")


# ===== auto.py =====
from vehiculo import Vehiculo   # aqui SI hace falta

class Auto(Vehiculo):
    def __init__(self, modelo):
        super().__init__(modelo)

    # no hay @Override: basta repetir el nombre.
    # si lo escribes mal, Python crea un metodo
    # NUEVO en silencio y nunca te enteras
    def describir(self):
        print(f"Auto {self._modelo}")

Polimorfismo, abstractas e interfaces

Un mismo llamado, muchas respuestas. Un for recorre círculos, rectángulos y triángulos sin saber con cuál está hablando, y cada uno calcula su área a su manera.

Momento ajáEmpieza la clase por el for polimórfico, no por la definición. Primero que vean el truco funcionando; recién después explica qué es una clase abstracta.
JavaFigura.java · Dibujable.java · Circulo.java
// ===== Figura.java =====
public abstract class Figura {
    public abstract double area();   // sin cuerpo:
}                        // el hijo DEBE implementarlo

// ===== Dibujable.java =====
public interface Dibujable { void dibujar(); }

// ===== Circulo.java =====
public class Circulo extends Figura implements Dibujable {
    private double radio;
    @Override public double area() {
        return Math.PI * radio * radio;
    }
    @Override public void dibujar() { }
}

// el for no sabe con que clase habla:
for (Figura f : figuras) {
    System.out.println(f.area());
}

# ===== figura.py =====

Composición y miembros estáticos

Dos ideas juntas: un Curso tiene alumnos (composición, no herencia), y el contador de alumnos creados pertenece a la clase, no a cada objeto.

Momento ajáSi creas tres alumnos, ¿hay tres contadores o uno? Esa pregunta, respondida corriendo el código, deja static aprendido para siempre.
JavaAlumno.java · Curso.java
// ===== Alumno.java =====
public class Alumno {
    private static int totalCreados = 0;   // UNA copia
    public static final double NOTA_MINIMA = 4.0;

    private String nombre;                 // una por objeto

    public Alumno(String nombre) {
        this.nombre = nombre;
        totalCreados++;        // sin "this": es de la clase
    }
    public static boolean aprueba(double n) {
        return n >= NOTA_MINIMA;
    }
}

// ===== Curso.java =====
public class Curso {
    private ArrayList<Alumno> alumnos;   // COMPOSICION
}
Pythonalumno.py · curso.py

Sobrecarga, toString y equals

Las tres preguntas que todo alumno hace tarde o temprano: por qué al imprimir sale Fraccion@1b6d3586, por qué dos objetos iguales dan false, y si se pueden tener dos métodos con el mismo nombre.

Momento ajáEl cruce que más confunde: en Java == compara referencias y equals() contenido. En Python es is el que compara referencias, y == el que compara contenido.
JavaFraccion.java
// ===== Fraccion.java =====
public class Fraccion {
    // SOBRECARGA: mismo nombre, distintos parametros
    public Fraccion sumar(Fraccion otra) { }
    public Fraccion sumar(int entero)    { }

    @Override public String toString() {
        return numerador + "/" + denominador;
    }
    @Override public boolean equals(Object obj) {
        Fraccion o = (Fraccion) obj;
        return num * o.den == o.num * den;
    }
}
x == y        // false: distinto objeto
x.equals(y)   // true:  mismo contenido
// a + b  ->  imposible: no hay sobrecarga de operadores
Pythonfraccion.py
# ===== fraccion.py =====
class Fraccion:
    # NO hay sobrecarga: el segundo metodo pisa
    # al primero. Se revisa el tipo a mano.
    def sumar(self, otro):
        if isinstance(otro, Fraccion): ...
        if isinstance(otro, int): ...

    def __str__(self):
        return f"{self._num}/{self._den}"

    def __eq__(self, otro):
        return self._num * otro._den == otro._num * self._den

    def __add__(self, otro):     # Java no puede hacer esto
        return self.sumar(otro)

x is y   # False   |   x == y   # True   |   a + b  funciona

Los cuatro movimientos

63 ejercicios · 9 hojas

Cada hoja de ejercicios repite las mismas cuatro operaciones sobre un código distinto. La repetición es deliberada: el alumno deja de traducir sintaxis y empieza a reconocer la estructura.

Movimiento 1

Agregar un atributo

Declararlo, sumarlo al constructor y arreglar todas las llamadas que quedaron cortas. En Java el compilador las señala una por una; en Python el error llega recién al ejecutar.

Movimiento 2

Agregar un método

Primero uno que hace algo (void), después uno que responde algo (con return). Esa distinción cuesta más de lo que uno espera.

Movimiento 3

Crear una nueva instancia

El ejercicio que demuestra el premio: agregar un objeto más sin tocar ni una línea de la clase, y en la demo 4, sin tocar el bucle que lo recorre.

Movimiento 4

Cambiar la privacidad

Pasar un atributo de private a public, hacerse millonario saltándose las validaciones, y volver atrás. En Python, recorrer los tres niveles: saldo, _saldo, __saldo.
